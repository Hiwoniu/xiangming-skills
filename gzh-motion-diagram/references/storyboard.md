# 选点与分镜

## 一、选点标准（第 1 步用）

判断标准只有一条：**这个知识点讲的是"过程"或"对比"吗？**

| 适合动 | 不适合动（做静态图或文字） |
|---|---|
| 东西在流动、排队、阻塞、合并、绕行 | 静态结构、分类、特征列表 |
| 两种方案的前后对比（A 堵 vs B 通） | 单纯的概念定义 |
| 时序问题（谁等谁、谁先谁后） | 开放问题、展望、结语 |
| 数量随时间变化，而且结论反直觉 | 已有截图且截图足够有冲击力的案例 |
| 多跳关系（A→B→C 逐步展开） | |

分档：
- **必做**：撑起文章骨架的核心机制，读者不看动画就理解不了。
- **推荐**：看动画能快一个量级理解，但文字也能讲清。
- **可选**：锦上添花，看篇幅决定。
- **不做**：写明用什么替代（静态卡片、对比图、文字）。

一篇文章的动图控制在 **6–8 张**，再多手机加载会卡。

清单表格式：

```markdown
| 档 | 编号 | 原文章节 | 动画讲什么（一句话） | 为什么非动不可 |
```

## 二、分镜规则（第 2 步，写完逐条自查）

- R1 **一张图一个知识点**。讲不完就拆成两张，不许塞。
- R2 结构固定为 **2–4 个内容场景 + 1 个总结页**。最常用的是"错误示范 → 另一种错误示范 → 正确方案 → 总结"（对比三幕），或"问题 → 机制 → 效果 → 总结"。
- R3 总时长 20–30 秒；内容场景每个 6–10 秒；总结页 ≥ 4 秒。
- R4 每个内容场景必须有：编号药丸（如"方案 ①"）、标题（≤17 字宽）、副标题（≤34 字宽）、结论条（1–2 个 chip，每个 ≤14 字宽）。
- R5 每个场景的舞台上只讲一个"动作链"（如：消息进来 → 排队 → 计数涨）。同一时刻最多 2 处在动。
- R5b 运动路径不许互相穿过：多个元素去不同目的地时，从各自目的地附近落入，不要都从同一个点飞出来横穿画面；队列前移要等队头离开后再动（延迟 ≥ 0.3 秒）。
- R6 结论条在切场前 ≥ 2.5 秒出现（读得完一个 chip 至少要 2 秒）。
- R7 总结页 = 药丸"一句话" + 金句（≤ 2 行，最多 2 处 accent 高亮）+ 可选的对比表或要点（≤ 3 行）。
- R8 所有事实标原文行号。

## 三、分镜模板（`storyboard.md`）

```markdown
# NN · <知识点名称>

- 原文：<路径>，第 X 节（L起-L止）
- 一句话：<这张图要让读者带走的那句话>
- 时长：XX 秒；场景切换点：sceneAt = [0, a, b, c]
- 新增元件：无 / <class 名：表示什么，为什么现有元件不够>

## 场景 1（0–a 秒）
- 药丸：方案 ①
- 标题：……（N 字宽）
- 副标题：……（N 字宽）
- 舞台：
  - 0.3s Session 框弹入
  - 0.5–5.0s 10 条消息依次进入，前一条没处理完的在左侧排队 [原文 L62]
  - …
- 定格：5.9–a 秒
- 结论条：✓ …… / ✗ ……  [原文 L62]

## 场景 2 …

## 总结页（c–DUR 秒）
- 金句：…… [原文 L72]
- 对比表 / 要点：……

## 自查
- [ ] R1 … R8 逐条打勾
```

参考：`examples/01-双层架构/storyboard.md`。
