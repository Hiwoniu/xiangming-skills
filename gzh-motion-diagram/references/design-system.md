# 视觉规范（向明图解）

系列里每一张图都用同一套规范。读者看懂第一张，后面就不用再学"这个颜色、这个形状代表什么"。**不许按单张图的喜好改规范。**

## 1. 画布与输出

| 项 | 值 | 说明 |
|---|---|---|
| 画布 | **1080 × 900**（6:5） | 公众号正文在手机上约 375px 宽，比 16:9 更不挤 |
| 时长 | **20–30 秒** | GIF 循环播放；超过 30 秒，10fps 下帧数就会超过 300 |
| MP4 | 30fps，`--quality delivery` | 由 check.sh 渲染 |
| GIF | 10fps，宽 900，96 色，`dither=none` | 由 check.sh 转码 |
| GIF 上限 | **≤ 5MB 且 ≤ 300 帧** | 超出即不合格（公众号对 GIF 有大小/帧数限制，留余量） |

## 2. 版式分区（单位 px，画布坐标）

```
┌──────────────────────────────────────────────┐ 0
│ padding 50 56                    水印(右上)    │
│ 编号药丸  (24px)                               │
│ 标题      (54px, 800)   ≤ 17 个汉字宽          │  head: 170 高
│ 副标题    (28px, muted) ≤ 34 个汉字宽          │
├──────────────────────────────────────────────┤ ≈220
│ 舞台 stage：1080 × 520，内部用绝对定位         │
│ （stage 左右各外扩 56，坐标从画布左边缘算起）   │
├──────────────────────────────────────────────┤ ≈740
│ 结论条 verdict：✓/✗ chip（30px）               │
└──────────────────────────────────────────────┘ 900
```

- 舞台内的元素用 `left/top` 摆位，运动只用 `x/y/scale/rotation/opacity`。
- 舞台内的主体元素要留出四周 ≥ 20px，不能贴边，也不能出界（入场动画除外）。

## 3. 颜色 token（只许用这些）

| token | 值 | 语义 | 用法 |
|---|---|---|---|
| `--bg` | `#F6F4EE` | 暖纸底 | 背景，全片唯一 |
| `--card` | `#FFFDF8` | 卡片底 | 所有框/卡片的填充 |
| `--ink` | `#1F2328` | 墨色 | 正文、普通框线、切场擦除 |
| `--muted` | `#5B616B` | 次要文字 | 副标题、说明文字 |
| `--line` | `#D8D3C7` | 分隔线 | 表格线 |
| `--track` | `#ECE7DC` | 槽底 | 进度条底槽 |
| `--well` | `#F3EEE3` | 凹槽 | 记忆行、列表行底色 |
| `--dotc` | `#DDD7C9` | 点阵 | 背景点阵 |
| `--accent` | `#E8590C` | **系统主角/结论** | Router、全局协调者、正确方案、金句高亮。**一张图里只给一个主角用** |
| `--bad` | `#C92A2A` | 问题 | ✗、冲突、堵塞、错误示范 |
| `--bad-bg` | `#F8E1E1` | 问题底 | ✗ chip 背景 |
| `--good` | `#2B8A3E` | 成立 | ✓ |
| `--good-bg` | `#E3F1E6` | 成立底 | ✓ chip 背景 |
| `--im` | `#2F6FEB` | IM / 聊天消息 | 事件来源色 |
| `--gh` | `#2D333B` | GitHub 事件（PR/Issue/评论） | 事件来源色 |
| `--ci` | `#9C6B00` | CI / 系统通知 / 定时任务 | 事件来源色 |
| `#fff` | 白 | 彩色底上的文字 | 只能用于彩色块上的字 |

`rgba(232,89,12,…)`（accent 的透明版）可用于光晕/高亮底，其他 rgba 只许是 `rgba(31,35,40,…)`（ink 阴影）。

## 4. 概念 → 视觉映射（系列统一，不许改）

| 概念 | 视觉 | 元件 class |
|---|---|---|
| 环境事件 / Trigger / 消息 | 彩色胶囊，内写来源缩写（IM / PR / CI / 邮件 / 日程） | `.bub.IM` `.bub.PR` `.bub.CI` |
| Session / 会话 / 进程 | 墨色描边圆角框，左上角写名字 | `.box` |
| Router / 全局协调者 | **accent 粗描边框**，标题 accent 色 | `.box.router` |
| Worker / 执行者 | 卡片框，描边用它负责的任务来源色 | `.box.worker` |
| 用户 / 人 | 墨色圆形头像，写"你" | `.avatar` |
| 进度 / 正在执行 | 细进度条 | `.bar > i` |
| 上下文 / 记忆片段 | 竖条（混乱）或标签行（有序） | `.stripe` / `.mem-row` `.mem-tag` |
| 路由信号 / 汇报 | 小圆点沿连线移动 | `.dot` |
| 连接 / 订阅关系 | SVG 实线，画线动画（dashoffset） | `line()` |
| 缺失的联系 / 不知情 | 红色虚线 + 红色"?"圆 | `line(..., dash=true)` |
| 错误的结果 / 混乱回复 | 红描边小卡片 | `.reply` |
| 正确的统一回复 | accent 描边长卡片 | `.good-reply` |
| 数量堆积 | 大号红色数字计数器 | `.big-count` + `counter()` |
| Fast Path / Slow Path | 实线 = 快路径，虚线 = 慢路径 | `line()` |

新知识点里出现上表没有的概念时：先想能不能复用已有元件；确实不能，再在模板"本图解专用"区新增，并把映射追加到 `storyboard.md` 的"新增元件"一栏，写清楚理由。

## 5. 字号（画布尺寸下）

| 层级 | 字号 | 字重 |
|---|---|---|
| 标题 | 54px | 800 |
| 金句（总结页） | 52px | 800 |
| 元件标题（Session / Router 层） | 34px | 800 |
| 结论 chip | 30px | 700 |
| 副标题 / 舞台说明 | 28px | 400–700 |
| 元件内文字 / 次要说明 | 24–26px | 400–700 |
| 最小字号（水印、小标签） | **24px，不得更小** | — |

画布 1080 宽在手机上缩到约 375 宽（×0.35）：24px 显示约 8.3px，已是下限。**能用 26px 就别用 24px。**

字体：`"PingFang SC", "Hiragino Sans GB", "Noto Sans SC", sans-serif`；数字胶囊和大号计数用 `"Helvetica Neue", Arial`。模板里已声明 `@font-face local()`，不要删。

## 6. 动效语言

| 动作 | 写法 |
|---|---|
| 标题入场 | 药丸左滑 → 标题上浮（expo.out）→ 副标题淡入（模板 `header()`） |
| 元件出现 | `scale 0.6→1` + `back.out(2)`，或侧滑 + `expo.out` |
| 消息移动 | `power3.out`，0.6–0.7 秒 |
| 被吸收/消化 | 缩到 0.4 + 淡出，`power2.in`，0.25–0.4 秒 |
| 强调 | 光晕脉冲（`pulse`）或数字弹跳（`yoyo`，repeat 1） |
| 连线 | dashoffset 画线，0.4 秒 |
| 结论条 | `back.out(2)` 依次弹出（模板 `verdict()`） |
| 切场 | 墨色整屏擦除（模板 `SCENES` 自动处理），不许自己写别的转场 |

背景层（点阵 / 光晕 / 幽灵大字）**必须静止**：GIF 是逐帧差分压缩，背景一动，体积就会翻 3 倍。

## 7. 水印
