# 01 · 双层架构

- 原文：`Super-agent 设计探索：迈向更自主的 Agent 系统.md`，第 2 节（L58-101）
- 一句话：把"维护连续性"和"并发执行"拆到两层，用户面对的始终是同一个 Agent。
- 时长：29.5 秒；sceneAt = [0, 7.4, 15.2, 25.2]
- 新增元件：无

## 场景 1（0–7.4 秒）单 Session 包办
- 药丸：方案 ①
- 标题：所有事件，塞进一个 Session（≈13.4 字宽）
- 副标题：上下文最连续，可它一次只能干一件事（17 字宽）
- 舞台：
  - 0.3s Session 框弹入；0.6s 左侧"排队中"计数出现
  - 0.5–6.2s 10 条 IM/PR/CI 消息依次进入。Session 一次只处理一条（进度条 2.3 秒），其余在左侧排队，计数涨到 7 [原文 L62：受限于单个 ReAct Loop 串行执行]
  - 每处理完一条，"上下文"区多一根彩色竖条，颜色混在一起 [原文 L62：多任务的中间细节混杂在一起]
- 结论条出现：4.6 秒（切场前 2.8 秒）
- 结论条：✓ 上下文连续 / ✗ 串行排队，细节搅成一锅 [原文 L62]

## 场景 2（7.4–15.2 秒）每条事件一个 Session
- 药丸：方案 ②
- 标题：每条事件，新开一个 Session（≈13.4 字宽）
- 副标题：并发拉满，可它们彼此不认识（14 字宽）
- 舞台：
  - 6 条消息各自进入 S1–S6，进度条同时跑完 [原文 L64：并发吞吐最高]
  - S1 与 S5 之间出现红色虚线和"?"，下方注释"都在改 PR #42，却互不知情" [原文 L64：缺少全局上下文，结果彼此割裂]（PR #42 是示意编号，原文没有）
  - 6 张"完成了！"同时飞向"你"，头像晃动，"到底听谁的？" [原文 L64：多个 Session 各自向用户响应，造成交互混乱]
- 结论条出现：12.6 秒（切场前 2.6 秒）
- 结论条：✓ 吞吐最高 / ✗ 结果割裂，回复打架 [原文 L64]

## 场景 3（15.2–25.2 秒）Router + Worker
- 药丸：方案 ③ · 双层架构
- 标题：Router 管连续，Worker 管并发（≈14.7 字宽）
- 副标题：Router 只接话、只派活；Worker 隔离执行，只向 Router 汇报（≈25 字宽）
- 舞台：
  - Router（accent）带"全局记忆"三行 [原文 L80：全局的序点、协调点和记忆]
  - 3 条新消息进入 Router → 画线 → 依次创建 Worker A/B/C，记忆里各记一行 [原文 L66、L80：只负责人类交互与任务分派]
  - 2 条后续消息进入 Router，以小圆点形式转给对应 Worker（本图不讲直通，直通留给 B 图）
  - Worker 用小圆点向 Router 汇报 [原文 L97：向 Router 层汇报状态]
  - "你"只收到 Router 一条回复 [原文 L97：由 Router 层统一向用户回复]
- 结论条出现：22.0 秒（切场前 3.2 秒）
- 结论条：✓ 上下文连续 / ✓ 多任务并发

- 金句：Session 应该是系统的实现细节，不该是用户的认知负担。[原文 L72]
